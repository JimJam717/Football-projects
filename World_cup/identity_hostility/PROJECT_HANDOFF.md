# Identity-Hostility Dashboard — Handoff & Project Spec

Last updated: 2026-07-16

## Project purpose
Build a model-flagged analytics dashboard that surfaces rates of identity-based hostile language (racial/ethnic and nationality/xenophobia) within the existing Swearing World Cup deduplicated Reddit corpus. This is a descriptive, model-flagged pipeline — not a human-annotated research study.

## High-level goals
- Read-only downstream analysis that uses only the post-deduplicated scored corpus (457,898 comments).
- Produce per-comment private flags and a public aggregate-only dashboard with clear methodology.
- Preserve privacy: no text, usernames, or comment IDs in public outputs; private review artifacts are gitignored.

## Data source
- Input: `data/processed/scored/*.jsonl` (100 files, deduplicated). Key fields: `match_id`, `subreddit`, `comment_id`, `timestamp`, `text`, `detected_language`, `detected_language_confidence`, `swear_count`.
- Dedupe reconciliation enforced against `data/collected/dedupe_report.json`.

## Tech stack
- Python 3.11; local venv reuse recommended (existing discourse venv contains torch, transformers, pandas, pyarrow, etc.).
- Model: Detoxify (multilingual) via the `detoxify` package (loaded from key `multilingual`).
- Data: JSONL input; PyArrow/Parquet for intermediate and aggregate storage; Pandas for transforms.
- Static dashboard: single self-contained HTML generated by Python embedding aggregate JSON.

## What was implemented (deliverables)
- `identity_common.py` — corpus loader, stage map, language gate, salted row-hash helper.
- `model_wrapper.py` — batched Detoxify wrapper with supported-language gating.
- `flag_detection.py` — lexicon + model flagging; writes private `comment_flags.parquet` (no text/author/comment_id; uses `row_hash`).
- `export_qa_sample.py` — writes private QA CSV (~150–200 rows) with full, untruncated text for human review.
- `aggregate_results.py` — computes and writes `aggregate_results.parquet` with tidy breakdowns (headline, by_match, by_stage, by_subreddit, by_language, overlap).
- `generate_identity_dashboard.py` — generates static broadcast-style dashboard HTML (6 panels) under `identity_hostility/dashboard/`.
- `verify_no_leak.py` — public-file leak checker scanning for text/author/comment_id and forbidden parquet columns.
- `docs/methodology_and_limitations.md` — short plain-language description of methods and limits.
- Unit tests: `tests/test_flag_logic.py` and `tests/test_aggregate_math.py` (33 tests) — all pass locally.

## What worked
- Reused existing discourse venv for core libs (torch, transformers, pandas, pyarrow) — only `detoxify` required install.
- Deterministic flagging pipeline: lexicon + model with explicit supported-language gating and repeatable salted hashes.
- Privacy guardrails enforced: private artifacts gitignored; public outputs aggregate-only; leak-checker provided.

## Known limitations / what did not work
- Detoxify requires a model key (fixed: `multilingual`) rather than a HF path. Initial mismatch caused an error but was fixed.
- Detoxify multilingual supports a limited language set (en, fr, es, it, pt, tr, ru). Comments outside this list are marked `model_unsupported` (lexicon still applies) — documented in the dashboard.
- Full-corpus model inference on CPU is time-consuming; the plan uses a subset validation run first.

## How to run (short)
1. Activate venv (recommend reuse: `worldcup_discourse\.codex_verify_venv\Scripts\activate`).
2. cd to `identity_hostility`.
3. Install detoxify: `pip install detoxify` (only if missing).
4. Subset validation: `python flag_detection.py --sample 5000`.
5. Full run: `python flag_detection.py` (long running).
6. QA: `python export_qa_sample.py` (review locally; tune `config/flag_config.json`).
7. Aggregate: `python aggregate_results.py`.
8. Generate dashboard: `python generate_identity_dashboard.py`.
9. Leak-check before sharing: `python verify_no_leak.py`.

## Privacy & guardrails
- Private files: `config/identity_lexicon.json`, `data/processed/identity_flags/comment_flags.parquet`, `data/processed/identity_flags/qa_sample.csv` — all gitignored.
- Public files: `data/processed/identity_flags/aggregate_results.parquet`, `identity_hostility/dashboard/identity_hostility_dashboard.html`, `docs/methodology_and_limitations.md`.
- Agent wrote scripts only; user runs model inference.

## Next recommended tasks
1. Run subset validation and tune thresholds via QA sample.
2. Consider moving lexicon to language-specific files and expanding non-Latin script coverage.
3. Optionally parallelize inference or run on GPU to speed full-corpus scoring.
